# 关卡学习：手机布局选择稿

这是独立预览，供选择布局后再改 Vue 页面。没有修改业务页面、主题配置、学习记录或依赖。

运行：`node .taste-skill/mobile-options/serve.cjs`，打开 http://127.0.0.1:18624/ 。
单屏：`?only=a`、`?only=b`、`?only=c`；主题参数：`&theme=jade-green`。

## 内容与用途

- 页面服务于识字学习，主要动作是选关并开始学习。
- 保留偏旁部首、一级、二级、三级字表的入口位置。
- 一级字表由项目真实数据构成，共 256 关，每关通常 10 字。
- 预览提取实际首 24 关，用于比较布局，不虚构学习内容。
- 三种方案统一显示零进度，避免通过不同数据制造视觉差异。
- 主要使用设备是手机；重点检查 390 × 844 和 320 × 568。
- 使用项目五套主题的原始 token，不设置独立品牌配色。
- 没有新增积分、连续打卡、关卡锁定等业务概念。
- A/B/C 的开始按钮打开本关十字预览，不进入业务流程或写记录。
- 顶部分类和底部导航用于比较布局位置；正式接入时复用现有业务导航。

## 三种结构与取舍

| 方案 | 构图 | 优点 | 取舍 |
| --- | --- | --- | --- |
| A 手帐字帖 | 字帖大字 + 九字预览 + 目录列表 | 字形有主次，安静、有阅读感 | 一屏可见关卡较少，目录需要向下浏览 |
| B 口袋闪卡 | 单关卡组 + 前后切换 + 快速选关 | 主动作集中，学习负担较轻 | 大量跳关时需要额外索引 |
| C 闯关棋盘 | 三列关卡棋盘 + 固定所选关预览 | 一眼看见更多关卡，选关效率高 | 小屏需要滚动棋盘，信息密度最高 |

原布局的模板感主要来自所有关卡等权、十字小格重复、标题/进度/按钮不断复现。这里分别以字帖、卡组、棋盘作为内容结构，而非只替换圆角和颜色。

## 看图后的判断

A 的大字与目录形成明确节奏，但整体偏安静；B 的卡组建立了最集中的开始入口，但跨关浏览较慢；C 的棋盘最便于跳关，代价是重复的关号与进度较多。三种都保留可辨认的识字内容，而不是通用数据面板。

自评（设计 / 易用 / 创意 / 内容，满分 10）：A 8 / 8 / 7 / 8，B 8 / 8 / 7 / 8，C 7 / 8 / 7 / 8。这是选型稿，不代表已经完成业务接入。

## 验证

- `capture.mjs`：15 张截图；五套主题切换；闪卡前后导航；棋盘选关；十字预览；无横向溢出；可点击按钮至少 44 × 44；浏览器无错误。
- 桌面比较画布为 1440 × 1110；实际手机画布为 390 × 844、320 × 568。小屏内容通过各方案内部纵向滚动，底栏和 C 的预览区保持可见。
- skill inspector（390px）：A 0 FAIL / 0 WARN；B 0 FAIL / 0 WARN；C 0 FAIL / 1 WARN。
- A 的 `headline-lines` 特例：真实的九字预览是三乘三网格，不是三行标题；保留内容与字形尺寸。
- C 的 `tiny-text` 提示来自重复的关号/进度副信息（12px）及底栏（11px），主要字形 35px、标题 25px。选型阶段保留；正式实现时可继续压缩重复元信息。
- Inspector 对未列入其内置高度表的 320px 宽使用 200px 高度，因此最终窄屏验证使用自定义 320 × 568 捕获，不采用其早期 320px 结果。
- `source-before.json` / `validation.json` 确认业务目标文件哈希未变。
- 本轮只生成布局预览，未执行或宣称 Vue 构建、类型检查、原生 App 验证；待用户选择后再接入现有技术栈并执行项目检查。
