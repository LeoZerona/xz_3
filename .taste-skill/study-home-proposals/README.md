# 学习首页 · 三版设计提案

本轮交付为独立设计稿与交互预览。正式 Vue 页面、路由、数据库、学习记录、依赖和锁文件均未修改。

预览地址： http://127.0.0.1:18635/ 。服务重启命令：`node .taste-skill/study-home-proposals/serve.cjs`。

## 现状与目标

当前学习首页只有字体介绍、三项统计和两个按钮。字体介绍占据最先被看到的位置，任务缺少进度表达，按钮之后没有今日学习内容可浏览。标题缺失、部分说明与标签只有 10px，底部非选中导航的对比度也偏低。

设计目标是让打开首页的人迅速知道：今天学什么、已经完成多少、下一步在哪里开始。通过实际字形、今日字单与已有学习入口提高内容密度。

已确认项目：Vue 3.4、Composition API、TypeScript、uni-app + Vite、Pinia、Vant、SCSS/CSS，H5 与 Android App-vue，pnpm 11。现有用户改动保留。本轮静态原型不代表 App 真机实现已经验证。

## 内容依据

- 产品为“字体学习”，首页的主任务是开始或继续每日学习。
- 主要使用手机，原首页内容最大宽度为 560px。
- 支持学习字体与对照字体两种角色。
- 样张使用项目内置的方正小篆体和优设标题黑，字体文件通过本地服务读取。
- 文字、拼音和稳定 ID 取自 `src/data/character-table/firstLevel/1.json` 的前 15 字。
- 字单属于设计展示样本，不是读取用户当天已分配的字单。
- 每日新学默认 15 字，复习目标 20 字，来自现有学习配置。
- 三种练习为认字、辨形、输入；正式完成规则维持现状。
- 原型提供未开始、学习中、完成三个展示状态。
- 学习中示例为前 6 字完成、9 字待学，40%；学习时长示例 5 分钟。
- 未开始为 0/15、0 分钟；完成为 15/15、12 分钟。复习统一为 0/20。
- 关卡学习、对照阅读、我、字体管理和计划修改都是原有入口。没有加入积分或打卡业务。

## A · 今日学习台（推荐）

回答的问题：今天的任务还剩多少，如何继续？

顺序：今日计划 → 正在学习的字体对照 → 今日字单 → 其他学习方式。

今日计划将三项统计、真实比例的进度条、继续学习和复习合为一个操作区。原来上下占据两行的字体介绍压缩成左右对照，保留字形与字体名称。今日字单直接展示小篆及完成状态，点击可放大查看双字体。

视觉采用浅灰页面、白色内容区、墨色主按钮；主题色仅用于进度。每个区域的内容量不同，避免所有模块都像同一种卡片。

适合每天打开即开始学习的用户。实现成本相对最低，可沿用现有 store 和主要跳转；新增首页字单需读取当天已分配内容。首屏尾部的其他入口可继续滚动查看。

## B · 字帖书桌

回答的问题：正在学习的字究竟长什么样，今天如何练？

顺序：大幅字体样张 → 今日任务 → 字单 → 对照阅读入口。

将系统“一个文字、两种字形”的关系变成首页主视觉。灰白样张区域直接显示小篆、现代字形、拼音和字体名称，提供“换一个字”。下方任务保持精简，字单像一条展开的字帖。

视觉采用纸页般的中性灰、较小圆角和墨色文字，没有纸纹图片或装饰插画。样张来自真实字体渲染。

适合希望产品更有识字与字体气质的方向。独特性强，但学习按钮在手机上比 A 更靠下；适合吸收其样张处理，而不一定完整照搬顺序。

## C · 字形探索

回答的问题：今天有哪些字值得先看一眼？

顺序：今日字形对照 → 可点击的五字选择条 → 精简计划 → 继续探索。

以实际字形为内容入口，点击字条会同步更换大字、对照字与拼音。淡主题色的字形区与白色任务区形成层级，提供更多可浏览内容。新学与复习仍收敛到清楚的操作入口。

适合初学者、偶尔进入首页和喜欢先浏览再练习的用户。内容感最强，但每日高频学习的操作路径不如 A 直接；平板第二列的长说明仍可继续缩短。

## 建议选择

优先选 A。若希望强化产品气质，下一步可以在 A 的字体对照区采用 B 的样张语言；控制样张高度，使“继续学习”仍留在首屏前半段。C 可作为内容探索方向保留。

三个方向都应在正式实现时映射项目现有主题 token。预览额外提供蓝、绿、夜间三种配色用于观察层级，不代表完整复刻系统的所有主题。

## 交互与实现边界

可体验：切换状态与配色、今日完整字单弹窗、单字双字体预览、B/C 换字、C 点字切换、原生对话框关闭与 Esc 返回。文字详情与字单使用同一份数据。

设计稿内的“开始/继续学习”打开字单预览，没有接入答题流程；更换字体、修改计划、底部导航等打开说明弹窗，没有写入系统。现有复习按钮没有完整业务处理，本轮只保留设计入口。正式落地仍需要单独确定复习流程。

未来实现保持 uni-app 页面结构与现有 Pinia stores；学习详情使用现有入口，展示文字需处理字库与字体加载状态。现有页面的数据库错误/重试能力应继续保留。不要从这个静态原型直接复制浏览器 DOM API 到 App 逻辑层。

`capture.mjs` 另外覆盖 320、390、768、1440px，共 12 次布局检查：无横向溢出，字体载入成功，按钮点击区域均不小于 44×44px，底部导航位于视口内；三种学习状态与核心预览交互均通过。蓝、绿、夜间配色已截图。`validation.json` 保存结果，校验的五个正式源码/配置文件哈希未变化。

原版 inspector 曾在数据库初始化时采到 0/0，伴随覆盖提示；该覆盖提示不作为原版稳定布局缺陷。`captures/before-loaded.jpg` 另行等待初始化结束后记录实际首页。稳定问题以缺少页面标题、10px 标签和空白内容区为准。

本轮没有修改 Vue/TypeScript 或构建配置，因此未运行正式项目类型检查、单元测试、生产构建和 E2E。H5 浏览器原型检查不等于 Android 真机验证；原型弹窗也不代表真实业务流程完成。

视觉复核第一轮：任务信息比原页完整，但导航被内容推到屏幕外、辅助字体偏小、C 宽屏留有空段。第二轮：改为固定壳与内部滚动、增大主要标签、调整字形比例；C 的计划面板仍出现拉伸留白。第三轮：面板按内容高度、辅助标签统一放大至 13px；保留 B 的低着色比例警告并说明理由。

最终主观评审（非用户测试分数）：

1. 问题与主视觉：A 的任务与行动最直接；B/C 的最大元素为真实学习字形，探索优先的意图明确。
2. 边界与密度：手机统一左右 20px，320px 为 16px；导航固定，内容滚动。宽屏无孤立窄卡片。平板仍可继续精修说明行长度。
3. 颜色：任务进度承接唯一主题色，导航与主按钮保持中性，C 使用主题色的浅色阶。
4. 一致性：6 + 9 = 15，6/15 = 40%；三版共享同一份字单、状态和时长，所有百分比按完成数计算。
5. 零与缺失：未开始真实显示 0，无进度短桩；日期固定为本次提案日期，不声称读取实时学习数据。
6. 图例：无统计图或多色图例；进度条带比例与进度值。所有字形/拼音在切换时同步。
7. 手机：导航没有侧栏占位，主操作可见，次要入口允许下滑；B/C 的学习按钮低于 A，是明确的体验取舍。
